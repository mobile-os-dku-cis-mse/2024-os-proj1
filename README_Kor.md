# 스케줄링 시뮬레이션
# CPU 스케줄링 기본 요구사항

## 부모 프로세스:
- 부모 프로세스에서 10개의 자식 프로세스 생성
- 부모 프로세스는 라운드 로빈 스케줄링 정책에 따라 자식 프로세스들을 스케줄링
- 스케줄링 매개변수(타임 퀀텀, 타이머 틱 간격 등)는 임의로 설정
- 부모 프로세스는 타이머 이벤트 등록을 통해 주기적으로 ALARM 신호를 받음
- setitimer 시스템 콜 참조 권장
- ALARM 신호는 주기적인 타이머 인터럽트(또는 시간 틱)역할
- 부모 프로세스는 실행 대기열(run-queue)과 대기열(wait-queue) 관리
    * 실행 대기열: 준비 상태의 자식 프로세스 보유
    * 대기열: 준비 상태가 아닌 자식 프로세스 보유
- 부모 프로세스는 자식 프로세스의 스케줄링 수행:
    * 모든 자식 프로세스의 남은 시간 할당량 관리
    * msgq를 통한 IPC 메시지로 자식 프로세스에게 시간 할당
    * msgget, msgsnd, msgrcv 시스템 콜 참조 (IPC_NOWAIT 플래그 주의)
    * 모든 자식 프로세스의 대기 시간 관리

## 자식 프로세스: (CPU 스케줄링 기본 요구사항)
- 사용자 프로세스 실행을 시뮬레이션
- 작업량은 CPU-burst와 I/O-burst의 무한 루프로 구성
- 실행은 두 매개변수로 시작: (cpu_burst, io_burst) - 무작위 생성
- 사용자 프로세스가 OS로부터 시간 할당을 받으면 진행
- 자식 프로세스는 CPU-burst 단계에서 진행
- 부모 프로세스가 현재 실행 중인 자식 프로세스에 IPC 메시지 전송
- 자식 프로세스가 msgq에서 IPC 메시지를 받으면 cpu-burst 값 감소

# I/O 관련 선택 요구사항
## 자식 프로세스:
- CPU-burst 후 I/O 요청 생성
- 남은 cpu-burst 추적
- cpu-burst가 0에 도달하면 다음 io-burst 시간과 함께 부모 프로세스에 IPC 메시지 전송

## 부모 프로세스:
- 자식 프로세스로부터 IPC 메시지 수신 시 io-burst 시작 여부 확인
- 자식 프로세스를 실행 대기열에서 제거하고 대기열로 이동
- 자식 프로세스의 io-burst 값 기억
- 시간 틱마다 대기열의 모든 프로세스의 io-burst 값 감소
- 프로세스의 남은 io-burst 값이 0이 되면 해당 프로세스를 실행 대기열로 복귀

## 프로그램 출력:
- 스케줄링 작업을 다음 형식으로 출력:
  (시간 t에서 프로세스 pid가 CPU 시간을 얻음, 남은 cpu-burst) 실행 대기열 덤프, 대기열 덤프
- 모든 작업을 schedule_dump.txt 파일에 출력
- 최소 1분 동안 모든 프로세스 실행
- (0 ~ 10,000) 시간 틱 동안의 스케줄링 작업 출력
